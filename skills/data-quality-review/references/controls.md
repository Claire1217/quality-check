# 控制验证协议

每题先声明目标、指标方向、合法基线、通过条件、允许随机性与误差范围。控制结论取决于这些声明，不使用统一 1/0、10% 或强制完全相等标准。

| 控制 | 检查 | 适用范围 |
|---|---|---|
| 环境与参考解 | 完整链路、提交、评分输出、资源 | 有可执行环境的题；缺参考解说明证据不足 |
| 重复评分 | 同提交多次评分的稳定性 | 允许随机性时用声明容差 |
| 无提交/空文件/空 JSON | 无效提交异常得分 | 按实际提交契约选择 |
| 常量/示例/starter | 无工作量基线、默认答案得分 | 区分合法基线与漏洞 |
| 跨实例答案 | 是否依赖本题输入 | 同结构且语义可比时 |
| 等价变换 | 重排、数值表示、合法替代答案 | 仅契约允许的等价变换 |
| 非法值/损坏答案/部分回答 | 异常分支、漏评、错误聚合 | 按实际格式与目标 |
| 权限与输出通道 | 真实 solver 用户能否读取答案或篡改 reward | 隔离环境中执行获授权的验证 |
| 资源记录 | CPU、内存、阶段耗时与声明是否匹配 | 实测，缺失填 null |

每个控制记录 task_version、protocol_id、输入或构造脚本哈希、预期及依据、实际结果、环境用户、证据路径和状态（passed/failed/blocked/not_applicable）。控制失败与工具故障分开。参考解高分不代替独立正确性检查。

可选 train-tasks 适配：固定 checkout commit，查看实际 CLI 后调用 `taskcheck.static`、`taskcheck.image_leak`、`taskcheck.run_probes`。默认阈值、训练集 canary、资源约束和平台打包规则可能不适合当前数据；保存原报告，并按本批协议独立解释结果，不静默改动上游结论。目录型提交、非 Harbor、答案键或 PPL 输入需要自己的适配，不能伪造 Harbor 结果。
