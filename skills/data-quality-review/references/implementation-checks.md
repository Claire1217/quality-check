# 补充审查清单

这些检查补充主 rubric，不另设重复缺陷计数。Implementation 阶段读取并记录可疑路径；需要执行的验证安排在控制阶段。必要时控制后更新原发现，保留前后证据。

## 评分器视角

- 追踪输入、校验、聚合、方向、归一化、阈值、异常处理和 reward 输出；异常不能静默成为有效模型零分。
- 检查常量、示例、默认 starter、部分作答与漏项是否获不合理分数。
- 按输入格式检查 NaN/Infinity、极值、布尔数值混用、重复键、缺字段、额外字段、顺序和非法 ID。
- 检查路径、链接、导入、代码执行、隐藏答案读取和 reward 篡改的可达性。
- 检查合法替代解、等价格式是否误拒，损坏参考答案是否降低相应得分。
- 将方法、调用次数、时间和资源限制映射到实际执行机制；未执行的限制按实际影响评级，不一律重大。

## 实例视角

- 题面中的数据规模、范围、格式、单位、示例与实际交付材料一致。
- 公共信息是否足够；是否存在隐藏约定、多解只接受一解、无法辨识的答案。
- 参考解是否使用允许信息，来源或生成过程能否解释答案；允许参考答案键，但不能用复制答案证明 Agent 任务可解。
- 空输入、边界值、并列结果、缺失值是否有合法处理。
- 文件名、顺序、大小等元数据能否推断答案；与直接读取隐藏答案分别记录。
- 有 authoring 材料时独立核验其声明；没有该目录本身不是缺陷，缺少的验证依据仍需披露。

## 发现记录

每条记录 issue_id、主 rubric、题目版本、严重程度、观察、影响、证据、确认程度、建议修复和验收条件。
blocker：评分或可解性根本失效、可实证近乎满分绕过等；major：实质影响正确性、公平性、隔离或复现；minor：影响有限。
严重程度与确认程度分开，静态已证实的严重缺陷不因未动态复现而自动降级；仅可疑路径不得写作成功攻击。
