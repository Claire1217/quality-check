# Implementation Review：通用与领域专项

先确定题型和收集目标，再映射所选上游 implementation rubric 的每条标准。报告明确分成两部分，分别给出结论与证据，不把所有 science 要求作为通用验收门槛。

## 通用质量

覆盖任务目标和验收条件一致、输入输出契约、材料完整、资源可行性、参考解真正解决问题、评分接受合法等价结果、负控制区分度、环境与结果可复现、答案隔离、防止无功得分以及执行安全。

难度、agentic 交互价值及去重是否为验收门槛，依据本批数据用途说明；不要求所有题都具备科研意义、科学创新性或发表价值。不存在公开答案的断言必须有明确搜索范围与证据。

## 领域专项

只启用与题目目标相关的检查。例如数学数值题检查定义、参考值来源与独立校验、算法/公式正确性、单位和数值容差依据、条件数与边界稳定性；其他领域使用相应规则。领域专项不是削弱数学正确性、评分正确性或复现要求。

研究意义、科学新颖性仅在收集目标明确要求时启用。本批不要求时记录不适用及理由，不算失败，也不能记为通过。科学措辞下的通用内核应保留并改写为适用描述，如“科学上成立的结果”对应“满足任务契约的正确结果”。

## 可追溯适配

保留上游原始 rubric、来源 commit 和哈希，另存本批 profile、逐项分组/适用性映射、改写后的 rubric 与 diff。用户授权的适配可用于正式审查，但必须注明“基于上游的适配版本”，不可宣称原版全部标准已通过。

未适用与证据不足分开：真正不适用给范围理由；需要检查却缺证据标 incomplete/INSUFFICIENT_EVIDENCE，不能用 N/A 隐藏缺失。实施审查结果、轨迹分析结果与主控最终判断分别保留。适用性在看分数之前确定，不为让某题通过而临时删项。
